# CNC 上下料技术方案

> 整理日期：2026-09-30。
> 来源：原仓库 `上下料/方案-整套脚本下发与监听-2026-09-07.md`、`上下料/适配-Aubo-C5-ARCS.md`、`上下料/模块划分-机加程序情况变化-2026-09-23.md`。
> 界面原型变更见 `../dev_docs/2026-09-04_上下料界面原型变更.md`。
> 技术栈：Vue + FastAPI。运动在 ARCS 工程 / Lua 执行。

## 1. 已确认的做法

1. 软件端根据工艺 / 料盘参数生成对应脚本。
2. 一次性下发整套脚本到机械臂控制器，由控制器自主执行运动。
3. 软件端不做逐步点动指挥，读状态和变量判断运行到哪一步。
4. 第一阶段机械臂为遨博 C5 + ARCS。门、卡盘、加工完成、允许取放由**控制器自带 PLC** 与程序交换。上位机不直连 CNC 做联锁。

这套「生成 + 整包下发 + 监听」适合作为运动层主方案。落地形态是：**运动脚本在臂端闭环；配方与联锁寄存器按约定读写；状态与步号由上位机读。** 不是纯监听，而是少指挥、勤握手。

真正要防的不是 Vue / FastAPI 的 HTTP 延迟，而是：机床联锁没有落到 PLC 时软件做不到只监听；变量当程序计数器会丢步、会脏读；下发成功不等于已加载、已选中、正在跑这一版；报警后不知道工件在哪，没有按步恢复。

## 2. 第一阶段范围

| 项 | 第一阶段 |
|---|---|
| 本体 | 遨博 C5 系列 |
| 控制器软件 | ARCS（Aubo Robot Control System） |
| 程序形态 | ARCS 工程 / Lua 脚本（示教器程序树最终也落到脚本） |
| 机床联锁 | 控制器自带 PLC ↔ 机器人程序（线圈 / 寄存器 / CI-CO） |
| 上位机 | Vue + FastAPI：生成、下发、启停、读状态；不直连 CNC 做门 / 卡盘 / 加工完成 |

第二阶段才考虑上位机走 OPC UA / FOCAS 问机床。

第一阶段明确不做：

- 上位机逐步点动指挥轨迹。SDK 里的 `MotionControl` 仅示教 / 点动调试，不进自动生产主路径。
- 上位机 OPC / FOCAS 参与门、卡盘、加工完成。
- 用 `IP:30001` 裸 TCP 灌自定义 `.script` 当生产下发。当前仓库 `script_sender` 的裸 socket 只是开发占位。

## 3. 职责

```
硬件安全回路     急停 / 光栅 / 安全门 / 卡盘确认（能硬线就硬线）
CNC I/O ──► ARCS 自带 PLC ──► 线圈/寄存器/CI-CO ──► 运动程序 Wait/置位
                                      ▲
                                      │ RegisterControl（同一地址）
                               FastAPI 采集 / 启停 / 下发
Vue              配置、下发、监控；禁止本地臆造设备状态
```

- **PLC**：门开到位、卡盘松紧、加工完成、允许进入、真空 / 夹爪确认等联锁；必要时转成程序能 Wait 的线圈。
- **运动程序**：轨迹、接近离开、夹爪时序；到联锁点 Wait PLC 信号；写步号 / 阶段 / 心跳。
- **上位机**：不参与联锁置位。生成并校验脚本，下发后 `loadProgram` 核对再 `runProgram`，读步号做界面，启动前可写配方（起点盘格、CRC）。

「只监听」成立的前提：PLC 已把机床信号变成程序能等到的量。上位机监听的是寄存器，不是 CNC 协议。上位机掉线时，PLC 联锁仍应能走完当前安全条件；急停仍走硬件。软件 Stop 不是急停。报警或掉线时禁止发 Start。

最大风险因此从「PC 必须写 CNC 应答」变成「PLC 梯形图 / 线圈映射必须和 Lua、SDK 用同一张地址表」。

## 4. 相对逐步指令要守住的点

| 点 | 说明 |
|---|---|
| 运动确定性 | 插补、加减速、接近离开不走局域网，不受网页 / API 抖动影响 |
| 上位机崩溃可续跑 | 脚本已在控制器里跑时，PC 掉线不一定立刻停；硬件安全回路仍要在 |
| 实现面小 | 不必做逐步指令队列和逐步超时重试 |
| 与现有代码同向 | `script_generator` / `script_sender` / collector / `/ws/robot` 已按此拆 |

仍要单独处理的问题：

1. **运行期几乎改不了工艺。** 料盘跳格、换抓手、某一格 NG 跳过、临时改安全高度，都要停、重生、再下发、再选程序、再启动。点位、格索引、速度倍率做成寄存器配方，脚本保持模板。
2. **变量当「走到哪」会漏、会乱。** 采集间隔默认 0.5s，短状态可能采不到。必须用单调递增步号 + 阶段枚举 + 心跳。漏采只记日志，不回推工艺，也不把中间动画当成已执行成功。
3. **下发成功不是执行闭环。** `sendall` 写完即成功，不读回执。必须核对程序名、长度 / 校验、当前运行程序，再允许 Start。
4. **异常恢复弱。** 只有步号、没有工件 / 夹爪 / 机床三态时，只能手摇。未知组合禁止自动继续。
5. **程序体积。** 料盘网格用原点 + 行列间距在臂端算，不要把每一格写成硬编码 MOV。
6. **一臂多机。** 运行中禁止覆盖正在执行的程序。
7. **前后端。** 多标签页同时启动 / 停止要有操作锁。WebSocket 断线后页面不能假装在线。Vue 禁止用本地推算关节或步号当真值。设备 IO 放采集子进程，禁止在请求线程里堵控制器。

## 5. 寄存器：逻辑名与 ARCS 地址

PLC、Lua、SDK 必须共用同一张表。改地址只改这一处配置。

Int16 范围 -32768～32767。步号、心跳不用复用的 bool；心跳用递增计数。

| 逻辑名 | ARCS 地址 | 类型 | 方向 | 谁写 | 含义 |
|---|---|---|---|---|---|
| STEP | Int16Reg 0 | int16 | 臂→PC | 程序 | 单调步号，关键动作前 +1，不要复用 |
| PHASE | Int16Reg 1 | int16 | 臂→PC | 程序 | 0 IDLE / 1 LOAD / 2 WAIT_CNC / 3 UNLOAD / 4 HOLD / 5 ALARM / 6 DONE |
| TRAY | Int16Reg 2 | int16 | 双向 | 启动前 PC，运行中程序 | 当前盘 |
| SLOT | Int16Reg 3 | int16 | 双向 | 同上 | 当前格 |
| CRC | Int16Reg 4 | int16 | 双向 | PC 下发后写入，程序校验 | 配方 / 脚本版本，启动前必须一致 |
| HB | Int16Reg 5 | int16 | 臂→PC | 程序周期 +1 | 通讯心跳；超时判通讯死 |
| RESULT | Int16Reg 6 | int16 | 臂→PC | 程序 | 0 无 / 1 OK / 2 NG |
| GRIP | BoolOut 0 | bool | 臂→PC/PLC | 程序 | 夹爪 / 真空有料 |
| CNC_READY | BoolIn 0 | bool | PLC→程序 | PLC | 允许取放 / 加工完成 |
| DOOR_OK | BoolIn 1 | bool | PLC→程序 | PLC | 门到位 |
| CHUCK_OK | BoolIn 2 | bool | PLC→程序 | PLC | 卡盘状态符合当前步 |
| CYCLE_REQ | BoolOut 1 | bool | 程序→PLC | 程序 | 请求机床开始加工 |

地址是联调前草案，冻结后三处一起改。

第一阶段上位机不写「机床已就绪」。CNC 走以太网是第二阶段：臂到 `WAIT_CNC` 后停住，PC 问机床，就绪后写启动应答（逻辑名 `R_CMD=4`），臂清令并继续。第一阶段这个应答由 PLC 的 `CNC_READY` 承担。

程序侧只等 PLC，不要等上位机 HTTP：

```lua
setInt16Register(0, 12)          -- STEP
setInt16Register(1, 2)           -- PHASE = WAIT_CNC
while getBoolInput(0) == false do
  sync()                         -- 等 PLC 的 CNC_READY
end
setInt16Register(1, 3)           -- PHASE = UNLOAD
```

`RegisterControl` 从 Lua（`setInt16Register` / `getInt16Register` / `setBoolOutput` / `getBoolInput`）、Python SDK 同名方法、自带 PLC / Modbus 从站 / EIP 读写同一套量。

## 6. 脚本、下发、监听、恢复

### 脚本生成

- 柜内放版本化模板工程，上位机优先下发参数块 / 点表；整包 Lua 作为备选。
- 备选 Lua 必须是 ARCS 语法（`movej` / `movel` / `setStandardDigitalOut` 等），不能沿用生成器里的 `MOVJ` / `CNC_SIGNAL` 伪代码。
- 生成物同时落脚本文件和 `steps.json`（步号 → 中文阶段 → UI 高亮），与 Int16Reg 0 对齐。
- 文件头写版本、CRC、机床号、生成时间、操作者；CRC 写入 Int16Reg 4。
- 网格用公式，不展开成上百条 MOV。
- 交叉校验：高速必须有足够安全高度、开闭阀不能同号、外部安全点未设则禁止整盘测试。

### 下发闭环

1. 停稳且非运行才允许覆盖程序。
2. 把文件放到 `${ARCS_WS}/program`（SFTP / U 盘导入 / 厂家文件接口，联调时确认一种）。
3. `RuntimeMachine.loadProgram(name)`。Lua 只写不带后缀的文件名。`loadProgram` 只加载柜内已有工程。
4. 读回程序名、大小、校验，核对当前运行名与 CRC。
5. 再 `runProgram`。TCP `sendall` 只是传输成功，不能当业务成功。

### 监听与采集

- 快通道（100–200ms）：Reg 0–6、Bool 联锁镜像、`getRuntimeState`、报警。
- 慢通道（约 500ms）：关节、TCP。`RobotState` 读姿态。
- 心跳停滞 → 通讯故障，UI 掉线，禁 Start。
- 步号回退 → 复位或重跑，刷新恢复建议。
- 步号跳跃 → 记漏采，按最新步显示。
- `getMainPtr` / `getAdvancePtr` / `getPlanContext` 只作调试，界面流程条以 STEP 为准。
- 落盘最近步号与三态，供掉电后恢复提示。
- 设备 IO 仍在 collector 子进程。`pyaubo-sdk` 不要在 FastAPI 请求线程里新建短连接。

### 异常与恢复

按 `PHASE + GRIP + 机床门/卡盘` 做恢复策略表（回安全点 / 先放料 / 只允许手动）。未知组合禁止自动继续。

### Vue / FastAPI

- 设备状态只来自 `/ws/robot`（或等价推送）。HTTP 只用于命令与配置。
- 命令单飞：进行中禁用重复 Start / Send。
- 操作者会话锁，或至少后写覆盖并审计。下发、启动、复位打操作审计。
- 空运行 / 低速 / 单步与自动生产模式分开。先 Mock 跑通步号协议，再上真机。

## 7. ARCS 接口

二次开发走 [pyaubo-sdk](https://pypi.org/project/pyaubo-sdk/)：JsonRPC 控工程，RTDE 可作高频状态。适配器放在 `backend/app/devices/`，例如 `aubo_c5_adapter.py`，`ROBOT_ADAPTER=aubo_c5`。采集子进程持有一条长连接。

| 能力 | 接口 | 用途 |
|---|---|---|
| 连柜 | `AuboApi` login | 长连接 |
| 使能 / 上下电 | `RobotManage` | servo_on / off |
| 状态 | `RobotState` | 关节、TCP、报警、运行模式 |
| 工程 | `RuntimeMachine.loadProgram(name)` | 从 `${ARCS_WS}/program` 加载 |
| 运行 | `runProgram` / `start` / `pause` / `stop` / `abort` | 对应现有 command |
| 辅助判步 | `getMainPtr` / `getAdvancePtr` / `getPlanContext` | 不能替代业务步号 |
| 业务变量 | `RegisterControl` | 与 Lua、PLC、现场总线共用 |

现有 `POST /api/script/send` 接 C5 后改为适配器内上传 + `loadProgram`。

C 系列柜体另有 CI/CO 数字量（手册约 16 入 / 12 出）。能硬线进 PLC 的机床信号优先硬线，再由 PLC 映到 BoolIn。

## 8. 机加程序模块（Sheet1）

> 来源：`资料/机加程序情况变化分析.xlsx` 的 Sheet1「一般流程」。
> 复审：取料计数与放料计数各记各的。本版范围是 Sheet1；Sheet3 只作边界约束。

Sheet1 做成 **6 个模块、4 段槽位**。运动骨架共用一条：工件上方 → 抓取或放置点 → 夹爪动作 → 检测 → 回到上方 → 离开点。握手信号、计数、碰撞区各自独立，不合成一个「工位」模块。

| 模块 | 槽位 | 合并方式 |
|---|---|---|
| 初始化 | 工程开头，只跑一次 | 内部五步不拆 |
| 旋转顶升料仓 | 取毛坯 或 成品下料 | 同一模板，按仓实例化。取、放契约不对调 |
| 料盘 | 取毛坯 与 成品下料可绑同一实例 | 取、放是同一模块的两个入口，计数各记各的 |
| 料框 | 成品下料 | 只用放料骨架 |
| 输送线 | 成品下料 | 放料骨架 + 自己的件数计数 + 满 N 件走一段 |
| 机床换料 | 机床段，双爪一次进出 | 进入、取、放、退出绑在一起；吹气是内部可选调用 |

单机双爪工程：

```text
初始化
→ 取毛坯槽：料仓.取 或 料盘.取
→ 机床换料：进入 → [吹气] → 取成品 → [吹气] → 放毛坯 → 退出并启动
→ 成品下料槽：料仓.放 或 料盘.放 或 料框.放 或 输送线.放
```

同一张料盘既取毛坯又放成品时，两个槽绑同一个料盘实例。「取料中」仍只关一次，不跟某一次计数加 1 绑在一起。毛坯盘和成品盘分开时，用两个料盘实例。料仓同理：一个物理仓一个实例。

配方关闭的模块不进入自动任务。绑定到槽位后，生成整包工程。料盘 / 料仓 / 公共配置可以共用配置入口；公共配置改的是配方组织方式，不把两种工位的信号契约合成一套。变更说明里的「取料完成」不是料盘关闭「取料中」的条件。

### 8.1 初始化

清报警、信号复位、变量复位、初始点、碰撞等级设定是一次启动序列。这里的碰撞等级是机床外等级。进机床时由机床模块改写，退出时改回来。

Sheet1 只要求进出机床时改碰撞等级。料盘区域另设碰撞等级来自 Sheet3，不写进初始化这一次设定里。

### 8.2 取放运动骨架

料仓、料盘、料框、输送线的中间段相同，做成内部原语，不单独占槽位。

- 「可能松夹两次」是夹紧动作上的参数，只出现在取毛坯。
- 料盘的 2～3 个方向偏移用原点 + 间距在模块里算，不把每一格写成独立步骤。取料游标和放料游标各自用这套网格参数。

### 8.3 料盘的取和放

共用的是信号和网格参数：料盘准备好、取料中、原点与间距。计数不共用。

取入口只推进取料游标（下一格毛坯），放入口只推进放料游标（下一格成品）。同盘时两套计数都挂在同一个实例上。输送线的「满 N 件」是第三套计数，留在输送线模块里。

关「取料中」只看料盘是否取完：

- 成品不回本盘：取入口在料盘取完时关闭。
- 成品放回本盘：取入口不关。放入口在料盘已经取完、并且本次放回完成后关闭。

放入口分两段：先等待料盘准备好，若能取不能放，提示人工料盘被手动关闭并停在这里；再次等待料盘准备好，再走放料。

取入口：等准备好 → 打开取料中 → 带偏移取料 → 上料爪夹料（可松夹两次）→ 检测 → 离开 → 取料计数加 1 → 仅按上面的规则关闭取料中。

放入口：门禁 → 再次等准备好 → 带偏移放料 → 下料爪放料 → 检测 → 离开 → 放料计数加 1 → 仅按上面的规则关闭取料中。

### 8.4 旋转顶升料仓的取和放

没有网格，没有计数。取和放共用模板，参数只换仓实例和允许信号地址。取放动作不对调。

- 取：等允许取 → 上料爪夹料（可松夹两次）→ 检测 → 离开 → 发取料完成。
- 放：等允许放 → 下料爪打开 → 检测 → 离开 → 发放料完成。

### 8.5 机床换料

进入时抬碰撞等级并打开换料状态，退出时发启动机床脉冲并恢复碰撞等级。这两头必须和取、放在同一次进出里。Sheet1 这一段默认是双爪一次进出。

| 块 | 处理 |
|---|---|
| 进入机床 | 必有。进机床前安全等待点、下料爪复位、检测、等加工完成、打开换料状态、进入机床、改碰撞等级 |
| 吹气 | 取前、取后各一个开关，调用同一段子程序 |
| 机床取料 | 下料爪夹成品。松卡盘在夹料前或夹料后，用参数选择，中间加延时 |
| 机床放料 | 上料爪打开。夹卡盘在松爪前或松爪后，用参数选择，中间加延时 |
| 退出 | 必有。退出安全点、启动机床脉冲、恢复碰撞等级 |

吹气子程序：吹气准备点 → 可选打开主轴旋转 → 打开吹气 → 吹气点 → 关闭主轴旋转 → 关闭吹气 → 可选检测主轴停止 → 吹气离开点。

松卡盘、夹卡盘留在取料、放料内部，不做成可拖动步骤。Sheet1 的机床放料离开点写成了「取料离开点」，语义与取料离开点相同，都是该动作结束后的离开点。

双爪一次进出的顺序写在机床模块里：进入时复位下料爪，下料爪取成品，上料爪放毛坯。

### 8.6 料框与输送线

两者都是：工件上方（偏移可有可无）→ 放置点 → 下料爪打开 → 检测 → 工件上方 → 离开点。

料框没有握手，也没有计数。输送线额外两步留在本模块内：工件计数加 1；满若干件，启动输送线走一段。这套件数和料盘的两套计数无关。

### 8.7 必须拆开的

| 拆开 | 原因 |
|---|---|
| 初始化 / 取毛坯 / 机床 / 成品下料 | 碰撞区、恢复方式、信号对象不同。初始化只跑一次，后三段进循环 |
| 料仓、料盘、料框、输送线 | 料仓是允许取/放与完成脉冲；料盘是准备好 + 取料中 + 两套网格计数；料框没有握手也没有计数；输送线是件数到了走一段 |
| 料盘取料计数与放料计数 | 合成一个游标后，同盘一循环会跳两格 |
| 料盘与料仓的动作契约 | 配置页可以和料仓放在同一个入口。动作信号仍按 Sheet1 分开 |
| 吹气与机床取放 | 取前、取后两行相同，作为机床模块内的可选调用 |
| 上料爪与下料爪的机床顺序 | 写在机床模块里，不拆成可拖动步骤 |

### 8.8 边界与未覆盖

Sheet3 的单爪顺序是另一种机床模块（两次进出）：机床取料 → 出去放成品 → 取毛坯 → 再进机床放料。四段槽位可以复用，单爪时机床槽被调用两次。不写进 Sheet1 双爪模块的默认顺序。

本版没有覆盖：

- Sheet2 的碰撞等级、速度等级、提前到位、卡片属性（程序属性，不是流程模块）。
- Sheet3 的二次定位、翻转台、双机床，以及料盘区域单独改碰撞等级。另开模块后再往槽位上挂。

### 8.9 现场口径

2026-09-15 的说明，不是 Sheet1 的逐步表。对照图：`资料/参考界面-料盘取料.png`。

- 基准程序是双夹爪、单机床。其他情况在这套程序上现场改。
- 一般换产只改标成 A 的项。调试或复杂换产才动 A 和 B。
- 上机用工具导入生成文件，不在示教器里从零搭。
- 界面做成大模块加少量常见指令，左侧展开后接近流程图。

## 9. 和仓库的差距与实施顺序

已有：工艺生成、单文件 TCP 下发、采集进程、WebSocket、Mock 适配器。

缺：Aubo C5 适配器（`pyaubo-sdk`）、ARCS 工程 / Lua 生成、`loadProgram` 闭环、与 PLC 共址的寄存器表、`steps.json`、恢复表、操作锁与审计。第一阶段不做 CNC 以太网握手。

实施顺序：

1. 冻结 Aubo C5 寄存器 / 线圈地址表（第 5 节，PLC、Lua、SDK 共用）。
2. 在 ARCS 自带 PLC 里做机床联锁，程序用 Wait / 读线圈，上位机不直连 CNC。
3. 脚本生成改为 Lua / ARCS 工程，经 `pyaubo-sdk` 放到 `${ARCS_WS}/program` 后 `loadProgram` + 核对再 `runProgram`。
4. 采集用 `RegisterControl` 快读步号 / 心跳，`RobotState` 慢读姿态。
5. Vue 用 `steps.json` 显示阶段；断线、报警禁 Start。
6. 写恢复表与空运行模式。
7. 第二阶段再考虑上位机直连 CNC（OPC UA / FOCAS）。
