# 02 程序已更新 → 工程待核对（D39 / D46 ②）

图：`v3-02-updated-1280x800.png`、`v3-02-updated-1024x640.png`；深色 `dark/v3-02-updated-dark-1280x800.png`、`dark/v3-02-updated-dark-1024x640.png`；首页 `v3-05c-home-blocked-1280x800.png`（见 05）。

## 1. 规则
- 引用自动跟到最新版本，不需要逐个确认。
- **只标受影响的节点**。直接受影响：节点调用的程序被改了（机床换料 → 主轴吹气 v3→v4）。**传递受影响**（D46 ②）：节点调用程序 A，A 里有一步调用了被改的 B（收尾 → 回安全点 → 主轴吹气），也一样标黄。
- 不另外做「间接引用」标记，和直接受影响的用**同一个「程序已更新」**，只多一行 14px 字说明来源：「来自 主轴吹气」。
- 工程变成「待核对」。核对之前首页「开始」禁用并写原因；重新下发、核对通过后黄标消失（M-06）。刷新后黄标和待核对状态保持一致。

## 2. 黄色节点
- 2px #D97706 边框 + 左侧 4px 色条（inset），底色不变（白 / 深色面）。
- 第一行右侧标签「程序已更新」：#FEF3C7 底，#B45309 字（4.5:1）。
- 被改的那个胶囊变黄：#FEF3C7 底 + #D97706 边 + #B45309 字，版本号显示新的（v4）。
- 传递受影响：胶囊（回安全点 v1）变黄，后面加 14 #B45309「来自 主轴吹气」，一行放不下时省略。
- 黄色节点同时是选中状态时：外面再加 3px 蓝浅色描边（outline，外移 2），黄框不被蓝框盖掉。
- 深色：边框和色条用 #F59E0B，字用 #FBBF24，底用 #3A2E0B（已过对比度审计）。

## 3. 页面其他地方
- 画布顶部提示条（48 高，黄）：「**2 个节点引用的程序已更新**，工程待核对。重新下发并核对后，首页才能开始。」只说数量，具体是哪些节点看画布。
- 页头下发状态：1280「下发 ✓生成 ✓上传 ✓加载 ○ 待核对（程序已更新）」；1024 胶囊「● 待核对 ›」。
  - 开发版本把「生成 / 上传 / 加载」也一起重置成 ○（程序变了，确实要重新下发），**接受**（10-04 美工验收）；关键是最后一格写「待核对（程序已更新）」。
- 属性面板（选中黄色节点）：顶部黄提示「程序已更新：主轴吹气 v3 → v4」+「10-02 10:41 保存。引用已自动跟到最新版本，重新下发并核对后标记消失。」调用列表里对应的那一行第二行写「已更新（原 v3）· 待核对」，颜色 #B45309。下面放 [去程序页查看 主轴吹气 ›]。
- 传递受影响的节点（1024 抽屉示例：收尾）：写清楚「「回安全点」调用了「主轴吹气」，所以这里也标黄」。
- **保存按钮**：工程本身没有改动，所以保存置灰，页头也没有「未保存」（D46 ③）。程序没有改动时同样置灰，版本不 +1，也就不会标黄。

## 4. 首页
「开始」禁用，按钮正下方写原因「工程待核对」（14 #C81E1E）；程序卡片里的黄色提示条写明哪几个节点，并给 [去工程编辑]。详见 05。
