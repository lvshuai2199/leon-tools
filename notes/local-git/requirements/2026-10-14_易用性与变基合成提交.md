# 易用性与变基合成提交

日期：2026-10-14
项目：local-git（本机工具，不进 LeonPro / personal-server）
分支：feat/local-git-history
现状：历史页已是一屏（左分支树贯通全高，右上提交图，右下文件 + diff）。工作区里 local-git/public/app.js、local-git/public/styles.css 的未提交改动保留，不提交、不回退。本次改动叠在上面。

## 要解决的两件事

1. 人不用懂 Git 术语，也能知道按钮会干什么。
2. 能在页面上把当前分支从最新一笔往旧的连续几笔收成一个提交。可以只合成、不换底；也可以在接到另一条分支后面时，把其中最新连续几笔收成一个。

布局保持两个 Tab（历史、变更），不改回三个 Tab。保留：拉取 / 推送 / 获取、分支树、提交图、文件 diff、变更页暂存与提交、回滚、贮藏后切分支、拣选、合并。

## 假设（写死）

1. 能勾的只有「从当前分支最新一笔往旧的一段连续提交」。中间空一笔、只勾旧的不勾新的，一律拒绝。
2. 没勾的更旧提交不丢。只合成：它们留在原地，新提交的父提交是勾选段最旧一笔的父提交。接到后面：它们按从旧到新各自 cherry-pick，勾选段再合成一个，放在最后。
3. 默认勾选：只合成时预勾最新 2 笔。接到后面时默认全不勾，效果等于现在的 git rebase。
4. 新提交说明默认用这段里最新一笔的标题，用户可改。空说明拒绝。作者用本机 git 身份，不保留原来的多个作者。
5. 勾选段里有合并提交就拒绝合成。原样接到后面仍走现有 git rebase（Git 默认会跳过合并提交），对话框里用中文提示，不改这条命令的行为。
6. 列表最多 30 笔，并且不用页面上 git log --all 的缓存来筛。只合成的下界：走到「另一条本地分支的祖先」或没有父提交的根提交就停，这两种都不放进列表。当前分支的上游不算另一条分支，所以已经推送、但只在当前分支上的提交仍能合成。
7. 点提交变快，只因为少发请求。lib/service.js 的 enqueue 仍是一条队列：读不插进写的中间，写不并发。P0 不拆队列。
8. 工作区不干净时，合成和接到后面都直接拒绝，不自动贮藏。贮藏只留给「切过去」。
9. 不加强制推送。push() 仍是 git push -u origin HEAD。会改写已经在上游里的提交时，只在确认框里用中文写明。
10. 点左侧分支叶保持不发请求。分支树渲染慢不在本笔记的 P0，也不改另一份性能笔记。
11. 测试只用 os.tmpdir() 夹具，不碰 D:\GitFiles 里的真仓库。
12. 不打开任何 git 编辑器，不用 git rebase -i。

## 页面上怎么点

左侧点当前分支，出现「合成最近几次」。默认勾着最新两笔，只能再往旧连续勾。说明默认是最新一笔的标题。确定后这几笔变成一个新提交，更旧的留着，其他分支不动。

左侧点另一条分支（本地或远程），「变基」改成「接到后面」。弹出当前分支上、那条分支还没有的提交。不勾，按「原样接过去」，就是现在的变基。从最新一笔往下连续勾至少两笔，按「合成勾选的再接过去」：没勾的更旧提交一笔笔接上，勾中的几笔合成一个放在最后。

工作区不干净不能做。冲突会取消并回到操作前。已经推送过的，确认框写明普通推送会被拒绝，工具不会强制推送。

## 功能模块

### 1. 分支按钮和确认框

点非当前分支：

- 检出 → 切过去。确认框：转到「目标」。你现在在「当前」。工作区不干净时沿用贮藏再切换，按钮文字用「先藏起改动再切换」。
- 合并 → 合进来。确认框：把「目标」合并进当前分支「当前」。有冲突会取消，仓库回到现在这样。
- 变基 → 接到后面。不直接变基，打开列表对话框。
- 删除仍叫删除。确认框：删除本地分支「目标」。当前分支不会动。还没合并过的删不掉。远程分支仍然没有删除。

点当前分支：显示「你在「xxx」。」和按钮「合成最近几次」。没有切过去 / 合进来 / 接到后面 / 删除。

工具栏「获取」加 title：只下载远程的新提交，不改你现在的分支。拉取确认框补上：有冲突会取消。推送不提强制推送。

代码：public/app.js 的 branchActions、action 里 checkout / merge / rebase / delete / pull。

### 2. 只合成，不换底

入口：当前分支的「合成最近几次」。打开前若 state.ws.dirty，toast「工作区有未提交改动，请先提交」，不发写请求。游离 HEAD 不显示这个按钮。

列表：GET /api/history-range?repo=&mode=squash
lib/git.js 新函数 historyRange。按从新到旧返回，最多 30 笔。git log --first-parent -n 31 走当前分支。某笔已经是另一条本地分支的祖先就停，它和更旧的都不要。没有父提交的根提交不要。每笔带 sha、shortSha、message、author、date、父提交个数、onRemote（有上游时，是不是 @{upstream} 的祖先）。不足 2 笔时 commits 为空，reason 写「当前分支上至少要有两笔自己的提交才能合成」。前端用 reason 做 toast，不打开空对话框。

对话框标题：合成最近几次提交。说明：把当前分支最新的连续几笔收成一个新提交。没勾的更旧提交留在原地。其他分支不动。有冲突或失败会回到现在这样。勾较旧的一笔就自动勾上比它新的全部；取消较新的一笔就自动取消比它旧的全部。默认勾最新 2 笔。说明框默认最新一笔的 message。确定按钮「合成一个」，少于 2 笔就禁用，旁边写「只能从最新一笔往下连续选，至少两笔」。勾中任意一笔 onRemote 时，说明末尾加：这里面有的提交已经推送到远程。合成会改写它们，之后普通推送会被拒绝。这个工具不会强制推送。

执行：POST /api/squash，body { repo, shas, message }。service 走现有 act → enqueue。git.squashTip：

1. assertClean、assertBranch。说明走现有 message()。
2. 服务端重算可合成链。shas 必须正好等于从 HEAD 往旧的连续 N 笔，N≥2。否则抛「只能从最新一笔往下连续选，中间不能空」，且不改仓库。
3. 范围内任一笔父提交多于 1 个：抛「这里面有合并提交，不能合成」，不改仓库。
4. 最旧一笔必须有父提交 P。记下 oldHead、当前分支名、所有 refs/heads 的 sha。
5. git reset --soft P，然后 git commit -m 说明。
6. 失败（含 nothing to commit）：git reset --hard oldHead。若 HEAD、分支名或其他本地分支 sha 不对，再 reset 一次并抛「合成失败，已回到操作前」。
7. 成功 notice：已把 N 笔合成一个。

不做：不 rebase -i，不 push --force，不改其他分支，不改没勾到的更旧提交，不贮藏。

### 3. 接到后面，可选合成

入口：非当前分支的「接到后面」。脏工作区同样先 toast。

列表：GET /api/history-range?repo=&mode=replay&onto=叶子的 checkout 名。onto 用现有 branchName，不能等于当前分支。来源是 git rev-list --reverse --no-merges onto..HEAD，返回给前端时改成从新到旧，最多 30 笔。超过 30 笔时 truncated，P0 不允许走合成，原样接过去仍允许（现有 git rebase）。另查 --merges，非空则 hasMerges。空列表 reason：没有可以接过去的提交。当前分支的改动目标里都有了。字段与 squash 相同，含 onRemote。

对话框标题：接到「目标」后面。说明：这些是当前分支上、「目标」还没有的提交。不勾选就原样接过去。从最新一笔往下连续勾选，可以把那几笔收成一个再接过去；没勾的更旧提交会一笔笔照原样接上，不丢掉。其他分支不动。有冲突会取消，仓库回到现在这样。hasMerges 时再加：其中有合并提交。原样接过去时会跳过合并点。要合成的话，请只勾没有合并点的最新连续几笔；勾到合并提交会被拒绝。默认全不勾。

按钮「原样接过去」：列表非空就可点，不看勾选，调用现有 POST /api/rebase。不要再套一层只有一句「变基」的 confirmBox。列表里有 onRemote 时加上同一句已推送警告。

按钮「合成勾选的再接过去」：不足 2 笔或不是从最新连续时禁用。会改写的是全部要接过去的提交（没勾的也会换成新 sha）。任一笔 onRemote 时加上已推送警告。

执行：POST /api/rebase-squash { repo, onto, shas, message }。现有 POST /api/rebase 和 git.rebase(repo, id, onto) 签名不动。git.rebaseSquash：

1. assertClean、assertBranch，onto 校验同 rebase()。
2. 重算 --no-merges 的 onto..HEAD，从旧到新。shas 必须是从最新往旧的连续后缀，且 ≥2。否则拒绝且不改仓库。
3. 记下 oldHead、分支名、全部本地分支 sha。前缀是比后缀更旧的提交。
4. 停在当前分支上 git reset --hard onto。前缀每一笔 git cherry-pick（保留原说明）。后缀每一笔 git cherry-pick --no-commit，最后 git commit -m 说明。
5. 任一步失败：cherry-pick --abort，必要时 rebase --abort、merge --abort，再 git reset --hard oldHead。不能留下 CHERRY_PICK_HEAD 或 rebase-merge / rebase-apply。HEAD 回到 oldHead，分支名不变，status --porcelain 为空。抛「接到后面没有完成，已取消」。
6. commit 报 nothing to commit：同样整段恢复，抛「接到目标上没有新的改动」。
7. 成功后再对一遍其他本地分支 sha。有变化就恢复并报错。notice：已接到目标后面，并把 N 笔合成一个。

不做：不 rebase -i，不 --rebase-merges，不 force push，不切到别的分支再操作。

### 4. 点提交马上出差异

现在点 data-sha 会 run("diff")。run 成功后 refresh → loadHome + loadRepo。loadRepo 先把 ws / log / diff 置空，再串行拉 workspace、git log --all、diff。run 里已经 loadDiff 一次，刷新又拉一次。

P0 改 public/app.js：

- data-sha：若 state.busy 直接返回。否则设置 sha，清空 logFile 和 picks，preferStash = false，只把 state.diff 置空，然后 render()，再 loadDiff()。不要 run()、refresh()、loadRepo()，不要把 state.ws / state.log 置空。
- historyFiles：已经有 sha 但 diff 还是空时，显示「正在读取这次提交…」，不要显示「没有文件差异」。
- 拣选目标的 onchange 同样只 loadDiff()。
- 失败只 toast。图和分支树保持上次的数据。diffSeq 保留。
- 检出、合进来、接到后面、合成、提交、推拉、贮藏、拣选、回滚仍然走 run() → refresh()。

不做：不把读请求移出 enqueue。不改 loadRepo 在写操作之后的整页重拉。

### 5. 安全

- 写前工作区不干净就拒绝，文件不动。
- 失败后当前分支名、HEAD、干净的工作区都回到操作前。不把仓库停在 rebase / merge / cherry-pick。
- 其他本地分支的 sha 不变。
- 不调用 push --force 或 --force-with-lease。
- 已推送只警告，不拦死。

## 测试用例（都在临时仓库）

- 三笔提交只合成最新两笔：最旧那笔 sha 还在，HEAD 的父提交是它，工作区文件等于合成前的树，说明是传入的文字。另一条本地分支 sha 不变。
- 不连续、只有一笔、含合并提交、或含根提交：拒绝，HEAD 与 porcelain 与操作前一致。
- 脏工作区调用 squashTip 和 rebaseSquash：拒绝，文件内容不变。
- 接到后面并合成：main 比分叉点多一笔，feature 上有 A B C，勾 B+C。结果当前仍是 feature，历史是 main 的新提交、然后 A、然后一笔 B+C 的合成。树里同时有 main 的改动和 A、B、C 的改动。main 的 sha 不变。
- cherry-pick 冲突：HEAD 回到操作前，porcelain 为空，分支名不变，.git 里没有 cherry-pick / rebase 进行中的目录。
- 空 shas 后端拒绝。现有「变基到 main」用例继续通过。push 的参数仍是 push -u origin HEAD。

## 不做

Shelve、changelist、三方合并、交互式 rebase 编辑器、不连续提交合成、合成后自动推送、保留原作者、提交签名、GitHub PR、深色皮肤、强制丢弃后切分支、强制推送、把工具做进 personal-server、加 npm 依赖。不提交、不回退历史页未提交改动。不改另一份「点分支加载慢」笔记。
