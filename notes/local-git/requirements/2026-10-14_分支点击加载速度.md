# 分支点击加载速度

日期：2026-10-14
项目：local-git（本机 Git 工具）
范围：只优化读取手感。检出、合并、变基、拣选、提交、暂存、贮藏还原仍做完、做对，冲突仍 abort。

## 结论

左侧分支叶（`data-leaf`）不发请求。用户感到的「加载」来自点提交图上的那一行（分支标签在这一行里面，点标签等于点提交）。这一下会走 `run("diff")` → `refresh()`，把 diff 拉两遍，并在中间串行扫完 `D:\GitFiles` 下每个仓库、再重拉 workspace 和 `git log`。

本轮没有跑成 `Measure-Command`（shell 被拒绝），下面没有毫秒数。慢是调用链上的重复和串行，不是猜出来的单次 git 耗时。开发时用文末命令补测。

## 哪次点击打到哪

| 点击 | 代码 | 请求 |
| --- | --- | --- |
| 左侧分支叶 | `app.js` `bind` 里 `[data-leaf]` | 无。只改 `selectedBranch` 并 `render()` |
| 提交图文字行，含行上的分支标签 | `[data-sha]` | `run("diff")` |
| 图左侧 SVG 圆点 | `renderGraph` 画在 `.graph-svg`，不在 `data-sha` 按钮里 | 无。点圆点选不中提交 |
| 历史页里换「拣选到」 | `#target` `onchange` | 有 `sha` 时同样 `run("diff")` |
| 换仓库 | `#repo-select` `onchange` | `run("repo")` 里先 `loadRepo()`，`run` 成功后再 `refresh()`，workspace 和 log 各两遍 |
| 检出 / 合并 / 变基 / 拣选 / 提交 / 暂存 / 贮藏 | `action` | `run` → 等对应 POST 结束 → `refresh`。这条必须留下 |

`run`：先整页 `render()`（按钮禁用），再执行 `fn`，成功后 `refresh()`，`finally` 再 `render()`。点一次提交最多整页重绘 3 次，图的滚动位置会丢。

`refresh`：`loadHome()` + `loadRepo()` + `render()`。

`loadRepo`：先把 `ws` / `log` / `diff` 置空（此时还没 `render`，所以等待过程中屏幕仍是旧图、旧差异，只是按钮灰了），再串行：

1. `GET /api/workspace`
2. `GET /api/log`
3. `loadDiff()` → 有 `sha` 时 `GET /api/diff`

点提交的实际顺序（全部经 `service.js` `enqueue`，一条链，不能重叠）：

1. `fn` 里的 `loadDiff` → `/api/diff`（这遍结果随后被 `loadRepo` 清掉）
2. `/api/home`
3. `/api/workspace`
4. `/api/log`
5. `/api/diff` 再一次

切仓库时 `sha` 已清空，`loadDiff` 在历史页不会发 diff。浪费是 workspace + log 各两次，再加一次 home。

## 每步实际在跑什么

`enqueue`（`service.js`）把读和写放在同一条 Promise 链。`act` 包住 workspace / log / diff / checkout / merge 等。一个慢的 `git show` 会挡住后面的读，也会挡住已经排队的写。

`home()`：`listRepos` 从 cloneRoot 往下走，每个仓库 `git.describe`：`branch --show-current`，没有分支再 `rev-parse --short HEAD`，再 `config --get remote.origin.url`。点提交、检出、切仓库都会走这里。

`git.workspace`，有分支时大约 6 次 git，串行：

- `branch --show-current`
- `rev-parse --abbrev-ref @{upstream}`
- `rev-list --left-right --count HEAD...@{upstream}`
- `status --porcelain=v1 -uall`
- `for-each-ref`（heads + remotes）
- `stash list`

`git.log`：`git remote`，然后 `git log --all --topo-order -n (limit+1)`，limit 最大 80。记录用 `raw.trim()` 去掉 `%x1e` 后面的换行。这个 trim 不能动，否则图上的连线会退回全是 bottom。

`git.diffPage` 在有 rev 时：

- `status --porcelain`（只为了 hint「工作区还有未提交改动」）
- `rev-parse`
- `commitPatch`：`git show -m --first-parent --format= --no-color`，整份补丁进内存
- `rev-list --parents -n 1`
- 有 target 时 `merge-base --is-ancestor`
- `diff.parse` 整份，`capFiles` 全局预算 800 行。预算用尽后，后面的文件直接不进列表
- 每个文件都 `sideBySide`。历史页只用 unified（`renderFile`），左右对比只在变更页

拣选片段不读这个被截断的页面。`cherryPickPartial` 自己再调一次完整 `commitPatch`，再用 `diff.select`。展示路径可以少读，这条不能改成截断补丁。

冲突取消保持原样，优化时不要动：

- 合并 `merge --abort`
- 变基 `rebase --abort`
- 拣选 `cherry-pick --abort`
- 拉取失败 `merge --abort`
- 贮藏还原冲突 `cleanConflict` / abort

## 优化目标

- 点提交后：图保持当前数据，文件列表和当前文件的差异尽快出来。
- 点左侧分支：不发请求；不要为了高亮整页重画图和差异。
- 不拿别的提交、别的仓库的 diff 充数。换 sha 先清掉旧 `state.diff`。
- 会改仓库的操作：等 git 结束再刷新一次。冲突继续 abort，不能停在 merge / rebase / cherry-pick 中间。
- 不做 Shelve、changelist、三方合并、交互式 rebase、提交签名、GitHub PR、深色皮肤。

## 假设

- 「分支位置」按代码判断：左侧叶不加载；图上的分支标签在 `data-sha` 按钮内，等于点提交；SVG 圆点当前点不到。
- cloneRoot 仍是 `D:\GitFiles`。home 的成本随仓库个数线性增加，具体个数和秒数未测。
- 大提交的整包 `git show` 会解析后再被 800 行预算截断，后面的文件可能不出现。
- 本工具是这些仓库的写入口。点提交时「工作区有未提交改动」用已经拿到的 `state.ws.dirty`，不在 diff 里再跑 `status`。工具外改了工作区时，这条 hint 可能旧；文件差异仍按 sha 现查，不缓存补丁。
- 写操作继续一次只跑一个。不让两次 checkout / merge 并行。

## 和后到需求的关系

- 「点提交只拉 diff」已经写进 `2026-10-14_易用性与变基合成提交.md` 的 P0，由那次实现一并做。
- 「点左侧分支不发请求」会被「分支图按分支显示」改掉：选一条分支看图时只多一次 `/api/log`，仍然不重拉 workspace。以那份新笔记为准。本笔记的 P1-2 不要再按「永远不发请求」实现。

## P0

只做能去掉重复等待、改动小、不改 git 语义的事。先做 P0，再谈把单次 diff 变小。

### P0-1 点提交和换拣选目标只拉 diff

- 改：`app.js` 的 `[data-sha]`、`#target` 的 `onchange`。抽一个小函数（例如放在 `loadDiff` 旁边），不要走 `run` / `refresh`。
- 做：设置 `sha` 或 `target` 后立刻 `state.diff = null` 并 `render()`；再 `await loadDiff()`；再 `render()`。`loadDiff` 已有 `diffSeq`，快速连点只保留最后一次。`historyFiles` 在有 `sha` 且 `diff` 还是空时写「正在读取差异…」，不要显示上一提交的文件，也不要显示「没有文件差异」。
- 不做：不调 `loadHome`、`loadRepo`、`/api/workspace`、`/api/log`。不改 `git.log` 的参数和 `trim`。不给 diff 做跨 sha 缓存。不禁用整页，避免 `run` 那种整页重绘。
- 验收：点一行提交，网络只有一条 `GET /api/diff?rev=`。图上的 sha 列表不变。文件列表对应该提交。再点另一行，屏幕上不能留下前一次的文件。改「拣选到」也只有一条 `/api/diff`，hint「目标分支已经包含」仍会更新。随后做一次检出，图和当前分支仍然会在 git 完成后刷新。
- 依赖：无。

### P0-2 切仓库只刷新一轮

- 改：`app.js` `#repo-select` 的 `onchange`。
- 做：清空 sha、文件、选中分支、贮藏后，只进入一次 `refresh()`（或 `run` 的 `fn` 不再自己 `loadRepo`，让 `refresh` 去拉）。保留这一次 `loadHome` + `loadRepo`，因为仓库变了，图和分支必须重拉。
- 不做：不要为了快跳过 workspace 或 log。不要在历史页没有 sha 时额外拉 diff。
- 验收：切一次仓库，`/api/home`、`/api/workspace`、`/api/log` 各一条，不是各两条。下拉框、左侧分支、图和 `git branch` / `git log --all --topo-order -n 80` 一致。
- 依赖：无，可和 P0-1 一起做。

## P1

### P1-1 单次 diff 不要读整包补丁

P0 之后，大提交仍可能慢：剩下的那条 `/api/diff` 还是整包 `git show`、整包 parse、再 `sideBySide`。

- 改：`git.js` 的 `diffPage`（展示）。`app.js` 的 `loadDiff`、`[data-log-file]`。测试 `test/git.test.js` 里「2 个文件」那条若断言到行数，一起改预期，不要改拣选断言。
- 做：有 rev、没有 scope 时，用 `git show -m --first-parent --name-status --numstat --format=` 列全文件和增删行。只对请求里的 `file`（没有就用列表第一个）再 `git show -m --first-parent --format= -- <path>`，解析这一份。展示仍可按文件截断，不要用一个 800 行预算把后面的文件丢掉。无 scope 时不要 `sideBySide`。有 rev 时不要为了 dirty hint 跑 `status`；历史页 hint 用已有 `state.ws.dirty` 在客户端补。父提交个数和「目标分支已经包含」可以留下（`rev-list --parents -n 1`、`merge-base --is-ancestor`），这两次比整包 show 小。点历史文件时若该文件没有 hunks，再 `loadDiff` 并带上 `file`。
- 不做：不改 `cherryPickPartial` / `commitPatch` 的完整补丁，片段拣选仍按完整补丁的 hunk 下标。不改变更页 `scopedDiff` 的左右对比。不改 log 的 trim、`--all`、`--topo-order`、上限 80。
- 验收：文件列表和 `git show -m --first-parent --name-status` 的路径一致，大提交不再少文件。点开的文件是 unified diff，和 `git show -m --first-parent -- <path>` 一致。变更页仍是左右对比。片段拣选后目标分支内容与现在相同，冲突仍 abort。`node` 跑现有 `local-git/test`。
- 依赖：P0-1。否则这份 diff 仍会被拉两遍。

### P1-2 点左侧分支不要整页重画

- 改：`app.js` `[data-leaf]`，以及 `branchActions` / 叶节点的 class。
- 做：只切换 `.is-on`，替换分支操作条（检出、合并、变基、删除）。`selectedBranch` 的含义不变。图的滚动位置保持。
- 不做：不在这里重拉 workspace。过滤框可以继续整页 `render`。
- 后续：若「分支图按分支显示」要求点叶后只看这一条，允许多一次 `/api/log?ref=`，仍然不要 `loadRepo`。本条「永远不发请求」作废。
- 验收：点叶，除了可选的那一次 log，没有 workspace / home / diff。操作按钮对应该分支。图没有跳回顶部。当前分支标记还在。
- 依赖：无。

### P1-3 改仓库之后不要再扫所有仓库

- 改：`app.js` `refresh`。必要时让 `loadRepo` 把当前仓库的分支写回 `state.home.repos` 里对应项。
- 做：检出、合并、变基、拣选、提交、暂存、贮藏、拉取、推送、获取：仍等 POST 成功，再 `loadRepo()` 一次（workspace + log + 按需 diff）。不要再 `home()`。下拉框上当前仓库的分支名用这次 workspace 的 `branch` 更新。
- 做：切仓库、克隆、保存目录仍 `home()`，否则新目录不会出现。
- 不做：不缩短 merge / rebase / cherry-pick 本身，不改 abort。不缓存整个 home 去跳过切仓库时的扫描。
- 验收：检出完成后下拉框是新分支，图上的标签是新 HEAD。`/api/home` 在这次检出里不出现。冲突合并之后工作区干净、仍在原分支（现有测试）。
- 依赖：P0-2 的「只刷新一轮」，避免又双倍 `loadRepo`。

## P2

### P2-1 读和写分开排队

- 改：`service.js` `enqueue` / `act`。
- 判断：不要两条写并行。写（checkout、commit、merge、rebase、cherry-pick、stash、stage、restore、fetch、pull、push）一次一个。有写在执行或排队时，读等它结束再开始，避免读到一半的合并。没有写时，读可以离开这条写链；读自己保持串行即可，不必并行。
- 不做：P0/P1 没做完不要先拆。拆完若点提交已经只剩一条小 diff，这条可以不做。
- 验收：慢 diff 进行时再点检出，检出要么在 diff 之后开始，要么 diff 被丢掉，但不能和 checkout 同时改同一个仓库。两个写不会重叠。冲突仍 abort。
- 依赖：P0、P1-1 之后用文末命令看读是否还堵写。

### P2-2 重绘时保住滚动；圆点也能选提交

- 改：`app.js` `render` / `renderGraph`。圆点若要能点，点击后走 P0-1 的同一条 `loadDiff`，不要 `refresh`。
- 做：整页 `render` 前后记下 `.graph-scroll` 和 `.diff-scroll` 的 `scrollTop`。这只影响写操作完成后的那次重绘。
- 不做：不把它当成点分支变快的手段。
- 验收：检出完成后图尽量停在原位置。点圆点和点文字行选中同一次提交，且只有一条 `/api/diff`。
- 依赖：P0-1。

## 开发时补测（只读，不要 fetch / pull / commit）

对 `D:\GitFiles\leon-tools`，以及一个历史更长的仓库（如 FullFunctionWelding、WeldingTools，以磁盘上真实路径为准）：

- `git log --all --topo-order -n 81`（pretty 与 `git.log` 相同）
- 一次大提交的 `git show -m --first-parent --format=`
- 同一次提交的 `git show -m --first-parent --name-status --numstat --format=`
- `git status --porcelain=v1 -uall`

工具若已在 `http://127.0.0.1:3792`，只对现有进程打只读接口计时，不要杀进程。对比 P0 前后点一次提交的请求条数：之前应看到 home + workspace + log + 两条 diff；之后应只剩一条 diff。

## 明确不做

- 不改 `local-git` 以外的产品（personal-server 等）。
- 不改 log 记录的 `trim`，不改 `--topo-order`，不把上限放到 80 以上来「显示更多」。
- 不用内存里上一提交的 diff 应付下一次点击。
- 不让 merge / rebase / cherry-pick / 贮藏还原为了快而停在冲突中间。
