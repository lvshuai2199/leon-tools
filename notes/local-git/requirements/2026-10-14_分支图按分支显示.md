# 分支图按分支显示

日期：2026-10-14
项目：local-git
分支：feat/local-git-history
不提交。不改 personal-server。不改 `2026-10-14_易用性与变基合成提交.md`。不写 README。

## 现状（以读到的代码为准，行号会漂）

- `lib/git.js` `log(repo, max)` 固定 `git log --all --topo-order -n`。上限 80，多取 1 条判断 `truncated`。format 含 `%x1e`。每条记录必须 `trim`，否则图上只有圆点没有连线。解析后走 `layout()`。git 失败时返回空图，不抛错。
- `lib/service.js` `log(id, max)` 只把 `max` 传下去。
- `server.js` `GET /api/log` 只读 `max`，没有 `ref`。
- `public/app.js` `loadRepo` 请求 `/api/log?repo=`，图永远是全部。开头会把 `ws` / `log` / `diff` 置空。
- 左侧 `data-leaf` 只改 `selectedBranch` 然后 `render()`，不发请求。`branch-filter` 只过滤树。
- `branchActions(findLeaf(...))` 用 `selectedBranch` 决定检出 / 合并 / 变基 / 删除。远程叶子的 `checkout` 已是 `refs/remotes` 下的短名（如 `upstream/topic`）。`refs/remotes/*/HEAD` 在 `branches()` / `branchTree()` 里被 `isRemoteHead` 跳过。
- `lib/graph.js` `layout(commits)` 输入从新到旧 `{ sha, parents }`。父提交不在这批结果里时画 `kind: "bottom"`。
- `lib/paths.js` `branchName` 拒绝空、超长、以 `-` 或 `/` 开头、以 `/` 或 `.lock` 结尾，以及 `..`、`//`、`@{`、`~`、`^`、`:`、`?`、`*`、`[`、`\`、空格。斜杠分支如 `feature/foo`、`upstream/topic` 可以通过。
- 读到的 `data-sha` 仍是 `run("diff")`。另一份实现会改成只 `loadDiff()`。本需求保持那个结果：点提交不整页重拉。

## 要解决的事

默认图仍是所有分支。用户可以选一条本地或远程分支，图只显示这条 ref 能走到的提交，并且能回到全部。选中这条分支时，检出 / 合进来 / 接到后面 / 删除还在。

## 假设

1. 用独立状态 `state.graphRef`。空字符串表示全部。它和 `selectedBranch` 分开：叶子 `is-on` 只表示选中（给按钮用）；图上「正在看」才表示当前图。两者可以不一致（选中 feature，图仍是全部）。
2. 点左侧叶子：`selectedBranch` 和 `graphRef` 都设为 `node.dataset.leaf`（本地名或 `remote/branch`）。再点同一条且 `graphRef` 已是它：不请求。不做成再点一下回到全部。
3. 点「全部」只清空 `graphRef`，不改 `selectedBranch`，按钮还在。已经是全部时不请求。
4. 打开仓库、切换仓库：`repo-select` 里先把 `graphRef` 置空，再走现有 `loadRepo`，因此是 `--all`。
5. 写出后的 `refresh` → `loadRepo` 若 `graphRef` 还在，log 的 URL 带这个 `ref`，避免提交后图跳回全部。`loadRepo` 拿到 `ws` 后，若 `graphRef` 非空且 `findLeaf` 找不到，先把 `graphRef` 清空再按全部拉。这条只发生在整页刷新，不是点叶子。
6. 点叶子或点「全部」只多一次 `GET /api/log`。不调用 `refresh` / `loadRepo`，不把 `ws` / `diff` 置空，不清 `sha`。该提交若不在新图里，图上没有 `is-on`，下面的 diff 仍留着。
7. `state.busy` 时不切图。
8. 单分支图仍用 `%D` 显示提交上的其他分支和 tag。只换提交集合，不在前端从 `--all` 结果里删提交。
9. query `ref` 缺省、空串、或 trim 后为空：当全部，不调用 `branchName`（它会拒绝空串）。
10. 页面不提供 HEAD 入口。API 若传入 `HEAD`，`branchName` 能通过，按 `git log HEAD` 处理，不是 `--all`。
11. 未知但格式合法的 ref 交给 git。失败抛中文「没有这条分支」，前端 toast，`state.log` 保持上一份成功数据。`--all` 失败仍返回空图，空仓库行为不变。
12. 不校验 ref 必须出现在 `branchTree`。40 位 sha 若被手填进 query，`branchName` 挡不住，git 会接受。页面没有这个入口。
13. 另一份笔记里的按钮文案（合成最近几次、接到后面）不要在本需求里改回去。叶子点击为了重画图可以 `render()`。那份笔记 P1「点叶子不整页 render」在这次让路：选分支看图必须更新图。
14. 测试只用 `os.tmpdir()`，不对 `D:\GitFiles` 做写操作。

## 页面上怎么点

历史页不变成第三个 Tab。左侧过滤框仍然只滤树。

图标题现在是「分支图」加一句说明。改成同一行：

- 按钮「全部」。`graphRef` 为空时带 `is-on`。
- 文字「正在看：全部」，或「正在看：feature/foo」「正在看：upstream/topic」。

左侧点一条可选分支（游离 HEAD 那条是 disabled，点不了）：

- 叶子保持 `is-on`。
- 当前分支仍是「合成最近几次」或现有的当前分支文案；其他分支仍是检出 / 合进来 / 接到后面（或现有的变基）/ 删除。远程仍无删除。
- 图换成这一条，标题写成正在看的名字。

回到全部：只点图标题旁的「全部」。

## 功能模块

### 1. 拼 log 参数

`lib/git.js`：

- 新增 `logArgs(ref, limit)`，返回数组，不含 `git()` 自己加的 `-c`。
  - `["log", "--all" 或 ref, "--topo-order", "-n", String(limit + 1), "--pretty=format:%H%x1f%h%x1f%an%x1f%aI%x1f%D%x1f%P%x1f%s%x1e"]`
  - `ref` 为空用 `--all`。有 ref 时数组里是这个 ref，且没有 `--all`。
- `log(repo, max = 50, ref = "")` 必须把 `logArgs` 的返回值交给 `git()`，不要另写一套参数。
- `limit` 仍是 `Math.min(Math.max(Number(max) || 50, 1), 80)`。
- `ref` trim 后非空：先 `branchName`。再 `isRemoteHead`，命中则抛「分支名不对」（挡 `origin/HEAD`）。ref 作为单个参数传入，不以 `-` 开头，避免被当成选项。
- 解析、`trim`、`decorateRefs`、`truncated`、`layout(commits.map(...))` 保持现在的做法。
- 有 ref 时 git 失败：stderr 像 unknown revision / ambiguous argument / bad revision 时抛「没有这条分支」，其它失败抛 scrub 后的原文。不要返回空 `commits`。
- 无 ref 时失败仍返回 `{ commits: [], graph: [], truncated: false }`。

`module.exports` 增加 `logArgs`。

### 2. 接口

- `lib/service.js`：`log: (id, max, ref) => act(id, (dir) => git.log(dir, max, ref))`。仍走 `act` / `enqueue`。
- `server.js`：`GET /api/log` 增加 `url.searchParams.get("ref")`，传给 `service.log`。缺省当空串。

### 3. 前端只多一次 log

`public/app.js`：

- `state.graphRef = ""`。切仓库时和清 `selectedBranch` 放在一起清掉。
- 新 `loadGraph()`：用序号丢掉过期响应。URL 在 `graphRef` 为空时是 `/api/log?repo=`，否则加 `&ref=`。成功且序号、`graphRef` 都没变才写入 `state.log` 并 `render()`。失败只 `showToast`，不改 `state.log`，不改 `ws` / `diff` / `sha`。请求前不要把 `state.log` 置空。
- `loadRepo` 里拉 log 的那一行改为带上当前 `graphRef`（空则不带）。不要删掉 `loadRepo` 开头对 `ws` / `log` / `diff` 的置空（那是切仓库和写操作路径）。拿到 `ws` 后按假设 5 处理已经不存在的 `graphRef`。
- `renderGraph`：`graph-head` 里放「全部」按钮（`data-graph-all`）和「正在看：…」。无提交时也要能看到这两个，不要只剩「还没有提交」把入口藏掉。截断文案仍是「只显示最近 N 条」。
- `bind` 里 `data-leaf`：设置 `selectedBranch`、`graphRef`，清贮藏选中（保持现在清 `stashId` / `preferStash` 的行为），调用 `loadGraph()`。不调用 `loadRepo` / `refresh`。
- `data-graph-all`：清空 `graphRef`，调用 `loadGraph()`。
- `data-sha`：若旁边的实现已改成只 `loadDiff()`，保持。不要改回 `run("diff")` / `refresh()` / `loadRepo()`。本需求不改这个点击，除非合并时发现它仍会整页重拉——那时只把它留成只 `loadDiff()`，与另一份笔记一致。

`public/styles.css`：`.graph-head button` 不要被拉满整行。`is-on` 用现有蓝底（`.tabs button.is-on` 那套即可）。

## 测试

都在 `local-git/test/git.test.js`，仓库在 `os.tmpdir()`。跑 `node --test test/git.test.js`。不碰 `D:\GitFiles`。

- `logArgs("", 10)` 含 `--all`、`--topo-order`，`-n` 后面是 `11`。
- `logArgs("feature", 10)` 和 `logArgs("upstream/topic", 10)` 含该 ref，不含 `--all`。
- 临时仓库：main 与 feature 各有独有提交。`git.log(dir)` 两边都能看到。`git.log(dir, 10, "main")` 看不到 feature 独有说明。`git.log(dir, 10, "feature")` 看得到，并且能走到 main 上的父提交；`graph.length === commits.length`，有非 `bottom` 的连线。
- 按现有 upstream 夹具：`git.log(dir, 10, "upstream/topic")` 包含这条远程上的提交。
- `git.log(dir, 10, "a..b")`、`"a b"`、`"a\\b"`、`"origin/HEAD"` 拒绝，文案含「分支名不对」，且不改 HEAD。
- `git.log(dir, 10, "no-such-branch")` 抛「没有这条分支」，HEAD 与调用前一致。
- `git.log(dir, 1, "main")` 在该分支至少两笔时 `truncated === true` 且 `commits.length === 1`。
