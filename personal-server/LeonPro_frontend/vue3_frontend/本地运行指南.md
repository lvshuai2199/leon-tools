# vue3_frontend 本地运行指南

本文说明如何在本机启动 `vue3_frontend`（LeonPro 个人工具平台 Web 端）。

项目路径：

```text
personal-server/LeonPro_frontend/vue3_frontend
```

技术栈：Vue 3 + Vite 6 + TypeScript + Element Plus + Pinia。包管理器必须使用 **pnpm**（`package.json` 的 `preinstall` 会拒绝 npm / yarn）。

---

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | `>= 18.0.0`（不要用 `20.6.0`，该版本有已知问题） |
| 包管理器 | pnpm（全局安装） |
| 浏览器 | 建议 Chrome / Edge 较新版本 |
| 后端（推荐） | `LeonPro_backend/SpringBoot`，默认端口 `8089` |

检查 Node 版本：

```bash
node -v
```

安装 pnpm（若尚未安装）：

```bash
npm install -g pnpm
```

---

## 2. 安装依赖

在 PowerShell 或终端中进入项目目录：

```bash
cd personal-server/LeonPro_frontend/vue3_frontend
pnpm install
```

说明：

- `.npmrc` 已配置国内镜像 `https://registry.npmmirror.com`，一般无需再改 registry。
- 首次安装可能较久，属正常现象。
- `pnpm install` 会触发 `husky` 的 `prepare` 脚本。若提示 Git hook 相关警告，一般不影响本地启动。

---

## 3. 开发环境配置

开发配置文件：`.env.development`。当前仓库默认值如下，**通常不用改即可启动**：

| 变量 | 当前值 | 含义 |
| --- | --- | --- |
| `VITE_APP_PORT` | `3000` | 前端开发服务器端口 |
| `VITE_APP_BASE_API` | `/dev-api` | 请求前缀，Vite 会把它代理到后端 |
| `VITE_APP_API_URL` | `http://localhost:8089` | 后端地址 |
| `VITE_APP_WS_ENDPOINT` | 空 | WebSocket 关闭（后端暂未提供 STOMP 端点） |
| `VITE_MOCK_DEV_SERVER` | `false` | 不走 Mock，走真实后端 |

请求链路：

```text
浏览器  →  http://localhost:3000/dev-api/xxx
Vite 代理  →  http://localhost:8089/xxx
```

如果后端不在本机 8089，改 `VITE_APP_API_URL` 后重启 `pnpm run dev`。

---

## 4. 启动前端

```bash
pnpm run dev
```

启动成功后会自动打开浏览器，访问：

```text
http://localhost:3000
```

也可以在局域网其它设备访问（Vite 已设置 `host: 0.0.0.0`）：

```text
http://<本机IP>:3000
```

---

## 5. 对接后端（推荐）

默认 `VITE_MOCK_DEV_SERVER=false`，登录和业务接口都打到本机 Spring Boot。

后端项目：

```text
personal-server/LeonPro_backend/SpringBoot
```

要点：

- Spring Boot 3.0.6，Java 21
- 开发环境端口：`8089`（`application-dev.yml`）
- 依赖 MySQL、Redis（连接信息见后端 `application-dev.yml`）
- 登录接口：`POST /auth/login2`

可用 IDE 运行 `springboot.Application`，或在后端目录执行：

```bash
cd personal-server/LeonPro_backend/SpringBoot
mvn spring-boot:run
```

启动后确认：

```text
http://localhost:8089
```

初始化账号（见 `SpringBoot/sql/leonpro_init.sql`）：

| 用户名 | 密码 |
| --- | --- |
| `admin` | `admin123` |

在前端登录页填写上述账号即可进入系统。

---

## 6. 仅前端、不启后端（Mock）

只想看页面、暂时没有后端时，把 `.env.development` 改成：

```env
VITE_MOCK_DEV_SERVER=true
```

然后重新执行 `pnpm run dev`。Mock 数据在 `mock/` 目录。

注意：Mock 接口形态与当前 LeonPro 后端不完全一致，登录和部分业务页可能对不上。日常开发请优先走真实后端。

## 7. 常用命令

在 `vue3_frontend` 目录下：

```bash
pnpm run dev          # 开发启动
pnpm run build        # 类型检查 + 生产构建，产物在 dist/
pnpm run build-only   # 只打包，不做 vue-tsc
pnpm run preview      # 预览 dist 产物
pnpm run type-check   # 仅类型检查
pnpm run lint:eslint  # ESLint 修复
```

## 8. 常见问题

### 8.1 `pnpm run dev` 被网络/代理打断（pnpm 11）

这不是 Vite 的 `/dev-api` 接口代理问题。pnpm 11 默认会在执行任何脚本前先跑一遍 `pnpm install`（`verifyDepsBeforeRun=install`）。安装会去拉 `registry.npmmirror.com` 上的可选平台包，代理或镜像抖动时会出现 `UND_ERR_DESTROYED`，整次启动直接退出。

`pnpm-workspace.yaml` 已改为：

- `verifyDepsBeforeRun: false`：本地已有 `node_modules` 时，`pnpm run dev` 直接起 Vite
- `allowBuilds` 批准 `esbuild` 等构建脚本，避免 `ERR_PNPM_IGNORED_BUILDS`

改完后重新执行：

```bash
pnpm run dev
```

如果只是想绕过检查、立刻启动：

```bash
pnpm --verify-deps-before-run=false run dev
```

需要重装依赖时再单独执行 `pnpm install`。不要用 `pnpm run dev` 当安装命令。

### 8.2 `npm install` / `yarn` 被拒绝

项目强制 pnpm。请改用：

```bash
pnpm install
```

### 8.3 登录失败 / 网络错误

1. 确认后端已在 `8089` 启动。
2. 确认 `.env.development` 中 `VITE_APP_API_URL=http://localhost:8089`。
3. 确认 `VITE_MOCK_DEV_SERVER=false`（走真实后端时）。
4. 打开浏览器开发者工具 Network，看 `/dev-api/auth/login2` 是否被代理到后端。

### 8.4 端口 3000 被占用

改 `.env.development`：

```env
VITE_APP_PORT=3001
```

重启 `pnpm run dev`。

### 8.5 页面空白

升级浏览器。过旧内核可能不支持可选链 `?.` 等语法。

### 8.6 依赖装完后 VSCode 组件/函数爆红

重启 VSCode。项目使用了 `unplugin-auto-import`，类型声明可能需要编辑器重新加载。

### 8.7 husky / git hook 报错

不影响 `pnpm run dev`。若安装阶段被 `prepare` 打断，可先确认当前目录处于 git 仓库内后再执行 `pnpm install`。

## 9. 和生产的区别

| | 开发 | 生产构建 |
| --- | --- | --- |
| 命令 | `pnpm run dev` | `pnpm run build` |
| 配置文件 | `.env.development` | `.env.production` |
| API 前缀 | `/dev-api` | `/prod-api` |
| 访问 | Vite 开发服务器 + 代理 | 需 Nginx 等把 `/prod-api/` 反代到后端 |

生产环境 Nginx 示例（部署 `dist/` 时）：

```nginx
location / {
    root   /usr/share/nginx/html;
    index  index.html;
    try_files $uri $uri/ /index.html;
}

location /prod-api/ {
    proxy_pass http://127.0.0.1:8089/;
}
```
