对应代码在 `personal-server/`：Web 前端 `LeonPro_frontend/vue3_frontend`，后端 `LeonPro_backend/SpringBoot`。分支：`dev`。

## 1. 轨迹分析（独立公开页）

**入口：** 工作台卡片，或直接打开 `/#/trace`（无需登录、无侧栏、无菜单权限）。

**能力：**

- 按插件解析工程：WeldingTools（裸 pose 数组）与 FullFunctionWelding（`full_apply_touch_offset`）。
- 同时导入 `.task` / `.task.script` / `.txt`，左侧任务树、中间 3D+2D 轨迹、右侧点位数据。
- 数据缓存在浏览器，刷新不丢；仅「清空数据」清除。
- `movec` 按「前一点 + 经过点 + 结束点」画圆弧，不再用直线弦。
- `movej` 橙色虚线只连接程序里相邻的接近/离开段，不跨焊道乱连。
- 月牙摆动等密点默认只画线；「显示轨迹点位」打开后标记会随密度缩小。
- 「显示任务树点位」：紫色空心圆标出任务树里带坐标的节点及名称（与红色参考点分开）。

**示例工程：** `LeonPro_frontend/elite-task/`（WeldingTools 直线/多层多道，FullFunction 直线+圆弧/多层多道）。Vite 启动时复制到 `public/elite-task`。

**主要文件：** `vue3_frontend/src/views/tool/trace/`（`index.vue`、`parse.ts`、`persist.ts`）。

## 2. 思维导图：服务端存储与外访链接

**入口：** 工具中心 → 思维导图 `/#/tool/mindmap`。

**能力：**

- Markdown 生成导图后可保存到数据库（表 `tool_mindmap`），PNG 落到本地目录。
- 每份导图有 `public_id`，可复制外访链接。
- 启动时自动建表；图片目录默认 `./data/mindmap`（`MINDMAP_DIR` 可覆盖），已加入后端 `.gitignore`。
- 开发代理对 `/public/mindmap/` 禁止缓存，避免改图后仍显示旧 PNG。

**主要文件：**

- 后端：`ToolMindmapController`、`tool_mindmap` 表（`SchemaPatcher`）
- 前端：`src/views/tool/mindmap/index.vue`、`src/api/tool/mindmap.ts`

## 3. 系统操作日志

**入口：** 系统管理 → 操作日志 `/#/system/oplog`。

**能力：**

- 记录写操作、登录、业务失败与未捕获异常（成功 GET/HEAD 不入库）。
- 字段含操作人、模块、路径、脱敏参数、IP、耗时、SUCCESS/FAIL/ERROR。
- 前端请求自动带 `X-User-Id` / `X-Username`，便于过滤器识别操作人。
- 未捕获异常由 `GlobalExceptionHandler` 转成统一 JSON，并写入 ERROR 日志。

**表：** `sys_operation_log`（启动自动创建）。

## 4. 注册码记录（原「操作日志」入口更名）

原先业务管理下的「操作日志」实际是注册码生成记录，已与系统操作日志拆开：

| 位置 | 名称 | 路径 |
| --- | --- | --- |
| 业务管理 | 注册码记录 | `/#/work/registration` |
| 系统管理 | 操作日志 | `/#/system/oplog` |

已有库会把菜单名 `操作日志`（`menu_registration`）自动更正为「注册码记录」，并补插 `menu_oplog`。

## 5. 系统数据包（随代码部署）

**入口：** 工作台底部「系统数据」卡片。

**用途：** 把当前环境的思维导图（含 PNG）和注册码配置打成 `system-data.zip`，放到代码里重新打包后，新环境启动自动导入。

**放置位置（二选一，classpath 优先）：**

1. `LeonPro_backend/SpringBoot/src/main/resources/seed/system-data.zip`
2. 运行目录 `seed/system-data.zip`

zip 本身不入库，目录里仅保留 `.gitkeep`。工作台可查看当前导图条数、注册码配置条数、数据包是否已放置。
