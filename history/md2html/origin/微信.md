### WXML模版

WXML是小程序框架设计的一套<font color="red">标签语言，用来构建小程序页面的结构</font>，作用类似于网页开发中的HTML

两者区别：

1. 标签名称
   - HTML(div,span,img.a)
   - WXML(view, text,image,navigator)
2. 属性节点
   - \<a <font color="red">href</font>="#">超链接\</a>
   - \<navigator <font color="red">url</font>="pages/home.home">\</navigator>
3. 提供了类似于Vue中的模版语法
   - 数据绑定
   - 列表渲染
   - 条件渲染

### WXSS样式

WXSS是一套<font color="red">样式语言</font>，用于描述WXML的组件样式，类似于网页开发中的CSS。

区别

1. <font color="red">新增了rpx尺寸单位</font>
   - CSS中需要手动进行像素单位换算，例如rem
   - WXSS在底层支持新的尺寸单位rpx，在不同大小的屏幕上会自动进行换算
2. <font color="red">提供了全局的样式和局部样式</font>
   - 项目根目录中的app.wxss会作用于所有的小程序也main
   - 局部页面的.WXSS样式仅对当前页面生效
3. <font color="red">WXSS仅支持部分CSS选择器</font>
   - .class和#id
   - element
   - 并集选择器、后代选择器
   - ::after和::before等伪类选择器

### JS逻辑交互

一个项目仅仅提供界面展示是不够的，在小程序中，通过.js文件来处理用户的操作。例：响应用户点击、获取用户所在位置

小程序中.js文件的分类：

1. app.js
   - 是<font color="red">整个小程序项目的入口文件</font>，通过调用<font color="red">App()函数</font>来启动整个小程序
2. 页面的.js文件
   - 是<font color="red">页面的入口文件</font>，通过调用<font color="red">Page()函数</font>来创建并运行页面
3. 普通的.js文件
   - 是<font color="red">普通的功能模块文件</font>，用来封装<font color="red">公共的函数或属性</font>供页面使用

## 小程序的宿主环境

<font color="red">宿主环境</font>指<font color="red">程序运行所必需的环境依赖</font>。例：Android和IOS系统是为两个不同的宿主环境。

==Tips：脱离了宿主环境的软件是没有任何意义的==

<font color="red">手机微信是小程序的宿主环境</font>，借助宿主环境提供的能力，小程序能够完成许多普通网页无法完成的功能，如：微信扫码，微信支付，微信登陆，地理定位，etc……

小程序宿主环境包含内容

1. 通信模型
2. 运行机制
3. 组件
4. API

#### 通信模型

##### 通信主体

小程序中通信的主体是渲染层和逻辑层，其中：

1. WXML模版和WXSS样式工作在渲染层
2. JS脚本工作在逻辑层

![image-20220824011101682](https://gitee.com/sfnss/typora-pic/raw/master/imgs/image-20220824011101682.png)

##### 通信模型

小程序中的通信模型分为两个部分：

1. <font color="red">渲染层</font>和<font color="red">逻辑层</font>之间的通信
   - 由微信客户端进行转发
2. <font color="red">逻辑层</font>和<font color="red">第三方服务器</font>之间的通信
   - 由微信客户端进行转发

#### 运行机制

##### 启动过程

1. 把小程序的代码包下载到本地
2. 解析app.json全局配置文件
3. 执行app.js小程序入口文件，调用App()<font color="red">创建小程序实例</font>
4. 渲染小程序首页
5. 小程序启动完成

##### 页面渲染过程

1. 加载解析页面的.json配置文件
2. 加载页面的.wxml模版和.wxss样式
3. 执行页面的.js文件，调用<font color="red">Page()创建页面实例</font>
4. 页面渲染完成

#### API

三大分类：

1. <font color="red"> 事件监听API </font>
   1. 特点：以<font color="blue">on</font>开头，用来<font color="blue">  监听某些事件的触发</font>
   2. 例：wx.<font color="blue">onWindowResize</font>(function callback)监听窗口尺寸变化的事件
2. <font color="red"> 同步API </font>
   1. 特点1：以<font color="blue">Sync</font>结尾的API都是同步API
   2. 特点2：同步API的执行结果，可以通过函数返回值直接获取，如果执行出错会抛出异常
   3. 举例：wx.<font color="blue">setStorageSync</font>('key','value')向本地存储中写入内容
3. <font color="red"> 异步API </font>
   1. 特点：类似于jQuery中的<font color="blue">$.ajax(options)</font>函数，需要通过success、fail、complete接收调用的结果
   2. 举例：wx.<font color="blue">request</font>()发起网络数据请求，通过success毁掉函数接收数据

## 页面导航

1. 定义：<font color="red">页面之间的相互跳转</font>

2. 小程序中实现页面导航的两种方式

   1. <font color="red">声明式导航</font>
      - 在页面上生命一个\<navigator>导航组件
      - 通过点击\<navigator>组件实现页面跳转

      - 调用小程序的导航API，实现页面的跳转

### 声明式导航

   1. 导航到tabBar页面

      <font color="red">tabBar页面</font>指的是被配置为tabBar的页面。

      在使用\<navigator>组件跳转到指定的tabBar页面是，需要指定的<font color="red">url</font>属性和<font color="red">open-type</font>属性，其中：

      - url表示要跳转的<font color="red">页面的地址</font>，必须以<font color="red">/</font>开头
      - open-type表示<font color="red">跳转的方式</font>，必须为<font color="red">switchTab</font>

      ![image-20220826035421243](https://gitee.com/sfnss/typora-pic/raw/master/imgs/image-20220826035421243.png)

   2. 导航到非tabBar页面（没有被配置为tabBar的页面）

      在使用\<navigator>组件跳转到普通的非tabBar页面是，需要指定的<font color="red">url</font>属性和<font color="red">open-type</font>属性，其中：

      - url表示要跳转的<font color="red">页面的地址</font>，必须以<font color="red">/</font>开头
      - open-type表示<font color="red">跳转的方式</font>，必须为<font color="red">navigate</font>

      Tips：导航到非tabBar页面时，<font color="red">open-type = "navigate"</font>属性可以省略

   3. 后退组件

      如果要后退到上一页面或多级页面，须指定open-type属性和delta属性，其中：

      - <font color="red">open-type的值</font>必须为<font color="red">navigateBack</font>，表示要进行后退导航
      - <font color="red">delta</font>的值必须是<font color="red">数字</font>，表示要后退的层级

      ![image-20220826040959814](https://gitee.com/sfnss/typora-pic/raw/master/imgs/image-20220826040959814.png)

## WXS脚本

### 概述

1. <font color="red">WXS</font>是<font color="red">小程序独有的一套脚本语言</font>，结合WXML，可以构建出页面的结构。
2. 应用场景：<font color="red">wxml中无法调用在页面的.js中定义的函数</font>，但是，wxml中可以调用wxs中定义的函数。因此，小程序中wxs的<font color="red">典型应用场景</font>就是“<font color="red">过滤器</font>”。
3. wxs与JavaScript关系
   1. wxs有自己的数据类型
   2. wxs不支持类似于WS6及以上的语法形式
   3. wxs遵循CommonJS规范

### 基础语法

1. 内嵌wxs脚本

   ```
   <view>{{m1.toUpper(username)}}</view>
   
   <wxs module="m1">
     module.exports.toUpper = function(str){
       return str.toUpperCase()
     }
   </wxs>
   
   ```

2. 定义外联的wxs脚本（在utils文件夹中新建tools.wxs文件）

   ```
   function toLower(str){
     return str.toLowerCase()
   }
   // 抛出方法
   module.exports = {
     toLower: toLower
   }
   ```

   

3. 使用外联的wxs脚本

   - <font color="red">module</font>用来制定引用模块名称
   - <font color="red">src</font>用来引入wxs文件，且必须是<font color="red">相对路径</font>

   ```
   <!-- 调用m2模块方法 -->
   <view>{{m2.toLower(country)}}</view>
   
   <!-- 引入wxs文件 -->
   <wxs src="../../utils/tools.wxs" module="m2"></wxs>
   ```

### WXS的特点

1. 与JavaScript不同
2. 不能作为组件的事件回调
3. 隔离性（wxs运行环境与其他JavaScript代码是隔离的）
   - wxs不能调用js中定义的函数
   - wxs不能调用小程序提供的API
4. 性能好
   - 在<font color="red">IOS</font>设备上，小程序内的<font color="red">WXS</font>会比JavaScript代码快<font color="red">2-20倍</font>
   - 在<font color="red">android设备</font>上，二者运行效率<font color="red">无差异</font>

### API Promise化

#### 基于回调函数的异步API的缺点

官方异步API默认基于回调函数实现

#### 什么是API Promise化

API Promise化，值得是通过额外的配置，将官方提供的，基于回调函数的异步API，升级改造为基于Promise的异步API，从而提供代码的可读性，维护性，避免回调地狱。

#### 实现API Promise化

安装miniprogram-api-promise第三方npm包。安装使用步骤：(指定版本号)

1. ```
   npm install --save miniprogram-api-promise@1.0.4
   ```

2. ```
   // 在小程序入口文件（App.js），只需要调用一次promiseAll()方法，即可实现异步API的Promise化
   import {promisifyAll} from "miniprogram-api-promise"
   
   const wxp = wx.p = {}
   promisifyAll(wx,wxp)
   ```

#### 调用Promise化之后的异步API

```
//返回值是Promise，故可用async进行优化
async getInfo(){
	//使用await结构出data属性，':'重命名为res
	const {data:res} = await wx.p.request({
		method:'GET',
		url:'',
		data:{
			name:'',
			age:''
		}
	})
	console.log(res)
	
}
```

### 全局数据共享

解决组件之间数据共享的问题

小程序中，可使用<font color="red"> mobx-miniprogram </font>配合<font color="red"> mobx-miniprogram-bindings </font>实现全局数据共享

- <font color="red"> mobx-miniprogram </font>用来创建Store实例对象
- <font color="red"> mobx-miniprogram-bindings </font>用来把Store中的共享数据或方法，绑定到页面或组件中使用

#### MobX

1. 安装

   ```
   npm install --save mobx-miniprogram@4.13.2 mobx-miniprogram-bindings@1.2.1
   ```

   Tips:记得删除miniprogram_npm目录，重新构建

2. 创建Mbox的实例

   ```
   import { observable,action } from 'mobx-miniprogram'
   
   export const store = observable({
   	// 数据字段
   	numA:1,
   	numB:2,
   	// 计算属性
   	get sum(){
   		return this.numA + this.numB
   	},
   	// actions 方法，用来修改store里的数据
   	updateNum1: action(function(step){
   		this.numA += step
   	}),
   	updateNum2: action(function(step){
   		this.numB += step
   	}),
   })
   ```

3. 将Store中的成员绑定到页面中

   ```
   import { createStoreBindings } from 'mobx-miniprogram-bindings'
   import {store} from '../../store/store'
   
   onLoad(options) {
       this.storeBindings = createStoreBindings(this,{
         store,
         fields: ['numA','numB'],
         actions: ['updateNum1']
       })
     },
   
   onUnload() {
       this.storeBindings.destoryStoreBindings()
   
     },
   ```
