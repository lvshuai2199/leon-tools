## WeldingTools 轨迹生成链路答疑（用户断点排查）
- `createTrajectoryManager` 只处理 `getBaseOscillation() != null`（配了摆动模式）的 shape 子节点；无摆动的段在 `setLinearCommands()` else 分支走 `getBaseCommandList()` 直接生成单条 MoveL/MoveC
- `getBaseOscillation()`（WeldShapeTaskNodeContribution.java:680）按 patterns 判断：crescent/circle/zigzag/trapezoid 返回对应摆动对象，其余（无摆动）返回 null；支持 `useSharedPatterns` 从父节点共享模式
- 用户场景确认：一个 WeldStart 下 5 个轨迹点，只有第一个段配了摆动，所以断点只见第一段进 TrajectoryManager —— 行为符合设计，不是 bug
- 段间拼接：每段 start 由 `getStartPose()`（WeldShapeTaskNodeContribution.java:627）回溯兄弟节点算出（首段取父 WeldStart 的示教点，后续段取前一段终点），即"下一段 start = 上一段 end"
- 直线终点位姿存储：`linearMovePoseKey` DataModel（WeldLinearTaskNodeAbstract.java:30），UI 示教按钮 `setLinearPoint()` → `requestUserToSetPosition` 回调写 `getCurrentTCPPose()`；另有 `setLinearMovePose()`（程序化，带异步 IK）和 `setLinearPointPose()`（法兰面示教）两条写入路径
