## 前端登录弹回登录页 bug 修复
- 症状：用户反馈"登录失败"；后端日志显示 6 次 `/auth/login2` 全部成功，登录后前端零请求 → 问题在登录成功后的路由生成环节
- **根因**：`api/system/menu.ts` 的 `getRoutes()` 返回普通数组，而 `store/modules/permission.ts:25` 对其调用 `.then()` → TypeError → `generateRoutes` 永远 reject → 路由守卫 catch 后 `clearUserData()` 清 token 并重定向回 /login
- 修复：`getRoutes()` 改为 `return Promise.resolve(jsonData)`
- 附带修复：
  - `store/modules/dict.ts` 的 `loadDictionaries` 直接 resolve 不发请求（后端无 /api/v1/dict/list，之前每次登录 404 且拦截器先弹"系统出错-报错"红色提示）
  - 登录页 catch 加 `ElMessage.error`，失败时用户可见提示
- 教训：之前"全链路验证通过"只到 API/编译层，未跑真实浏览器登录流程；`import.meta.glob` + 静态路由方案中，API 返回值类型必须与消费端 `.then()` 兼容
